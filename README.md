# 文件夹大小分析器

看某个文件夹到底被什么占满了。选一个目录，它把里面每个子文件夹、每个文件占多大，从大到小排给你看。

## 怎么用

1. 打开 **`FolderSizeAnalyzer` 文件夹**，双击里面的 **`FolderSizeAnalyzer.exe`**
2. 点"选择文件夹"，挑你要看的目录
3. 等它扫完。列表里大的排前面，一眼看出谁最占地方

不需要装 Python，也不需要装别的，双击就能跑。

> ⚠️ `FolderSizeAnalyzer.exe` 和它旁边的 `_internal` 文件夹是**一整套**。
> 要拷给别人，就把整个 `FolderSizeAnalyzer` 文件夹一起拷，只拷 exe 会打不开。

## 有什么功能

- 边扫边显示，扫大目录不会卡死
- 可以暂停 / 继续 / 停止
- 列表里每个文件夹 / 每个文件都显示**大小**和**占父目录的比例**
- 按名字搜索过滤
- 右键可以对某一层排序：按大小（升/降）、按名称（A-Z / Z-A）
- 右侧显示文件类型统计（哪类文件最占地方）
- 默认跳过 `node_modules`、`.git`、`build`、`__pycache__`、`.idea`、`dist` 这些目录——它们是缓存和依赖，数量多、体积虚高，不算你的真实数据
- **跳了多少、跳了哪些，界面右下角「已跳过」那一块全列出来**，右上角也有个「已跳过」的数字。一眼就知道跟资源管理器的差额去哪了
- 想把这些也算进去，勾一下工具栏的**「含缓存/依赖目录」**，它会重新扫一遍（会慢一些，因为要多读十几万个文件）

## 为什么数字跟资源管理器对不上

资源管理器对同一个文件夹给你**两个**数字：

| 资源管理器写的 | 实际是什么 |
|---|---|
| **大小** | 所有文件自己有多大，加起来。**本工具算的是这个** |
| **占用空间** | 按硬盘最小块（一个块通常 4 KB）算的实际占用。**一定比「大小」大** —— 一个 1 字节的文件也要占掉一整块 |

所以拿本工具的数字去对**第一个**数字（大小），别对「占用空间」。

剩下对不上的部分，界面里都写出来了：

1. **被跳过的目录** —— 右下角「已跳过」那一块。用「合计跳过」加上「总大小」，就是「真实总计」
2. **读不到的项** —— 没权限、文件正被占用之类。底部状态栏会写「读取失败 N 项」

> 实测 `D:\Project\codex`：默认模式 11.47 GB + 跳过 6.27 GB = **17.74 GB**，
> 资源管理器说 17.6 GB，对得上。

| 文件 | 是什么 |

## 改代码之后

```bash
# 1. 跑测试，确认没扫坏
python -m unittest test_file_size_analyzer

# 2. 直接看效果（不打包）
python file_size_gui.py

# 3. 重新打包（输出到项目根目录的 FolderSizeAnalyzer 文件夹）
python -m PyInstaller --noconsole --onedir --name FolderSizeAnalyzer --distpath . --workpath _build_tmp --specpath _build_tmp --noconfirm file_size_gui.py
# 打完把里面那个旧文件夹整个替换掉

> ⚠️ 必须用 `--onedir`（文件夹版）。不要用 `--onefile`（单文件版）——单文件每次双击都要
> 先把 11MB 解开摊到临时目录，启动要多等好几秒。
```

## 技术说明（不了解也别硬看）

- Python 3，**只用标准库**（tkinter 画界面 + os.scandir 扫盘），没有任何第三方依赖
- 扫描在后台线程做（`AnalysisThread`），用 `os.scandir()` 流式扫描，分批把结果推给界面，所以界面不卡
- 扫描分**两段**：第一段先把目录树交出来（这部分快），第二段在后台把「被跳过的目录」单独量一遍
  （`_measure_skipped`），量完再补到界面上。所以树会先出来，差额那个数字晚几秒才出现
- 界面是浅色扁平风格：白底卡片 + 单一蓝色强调色，文件夹粗体深色、文件浅灰，一眼分得清
- 自带高 DPI 支持（`SetProcessDpiAwareness`），所以在缩放 125% / 150% 的屏幕上文字也是清晰的，不会糊
- 大小是"累积值"：文件夹自身的大小 = 里面所有东西加起来（目录节点直接缓存，不用每次重算）
