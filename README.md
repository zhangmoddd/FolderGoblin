# 文件夹大小分析器

看某个文件夹到底被什么占满了。选一个目录，它把里面每个子文件夹、每个文件占多大，从大到小排给你看。

## 怎么用

1. 打开 **`FolderSizeAnalyzer` 文件夹**，双击里面的 **`FolderSizeAnalyzer.exe`**
2. 点"选择文件夹"，挑你要看的目录
3. 等它扫完。列表里大的排前面，一眼看出谁最占地方

不需要装 Python，也不需要装别的，双击就能跑。

> ⚠️ `FolderSizeAnalyzer.exe` 和它旁边的 `_internal` 文件夹是**一整套**。
> 要拷给别人，就把整个 `FolderSizeAnalyzer` 文件夹一起拷，只拷 exe 会打不开。

## 有什么功能

- 边扫边显示，扫大目录不会卡死
- 可以暂停 / 继续 / 停止
- 列表里每个文件夹 / 每个文件都显示**大小**和**占父目录的比例**
- 按名字搜索过滤
- 右键可以对某一层排序：按大小（升/降）、按名称（A-Z / Z-A）
- 右侧显示文件类型统计：**占比**（这类文件占总共大小的百分之几）、**文件数**、**大小**；按大小从大到小，最多列 19 类，标题旁边写着"只列最大的 19 类，共 48 类"，所以数字加起来对不上总数是正常的
- **没有任何忽略名单** —— `node_modules`、`.git`、`build`、`__pycache__` 这些也全都算进去，跟资源管理器口径一致
- 右下角有个「未计入」面板，专门列**没算进总数**的东西（符号链接、读不到的文件）。正常情况下它写「无」
- **用多少摆多少**：扫描时只摆顶层，点开哪个文件夹才摆哪个里的东西，所以又小又目录也不会卡
- 收着的文件夹底下会垫一条灰字小行，写着**里面有几项**（比如 `12 项`）。那不是进度条，是为了让 Windows 把展开箭头画出来；点开就换成真内容，那行自动消失

## 为什么数字跟资源管理器对不上

资源管理器对同一个文件夹给你**两个**数字：

| 资源管理器写的 | 实际是什么 |
|---|---|
| **大小** | 所有文件自己有多大，加起来。**本工具算的是这个** |
| **占用空间** | 按硬盘最小块（一个块通常 4 KB）算的实际占用。**一定比「大小」大** —— 一个 1 字节的文件也要占掉一整块 |

所以拿本工具的数字去对**第一个**数字（大小），别对「占用空间」。

剩下可能对不上的，右下角「未计入」面板会全部列出来，绝不会偷偷少算：

- **符号链接 / 快捷方式** —— 不跟进去（跟进去可能绕圈），会列出个数
- **读不到的文件/文件夹** —— 会按原因分类列出来，见下一节
- 都没有时，面板写「无 —— 所有文件都算进去了」，说明数字是完整的

## 读不到东西是怎么回事

面板会把读不到的按**系统给的原因**分类，说法都是人话：

| 面板上写的 | 实际意思 | 该干什么 |
|---|---|---|
| 拒绝访问 | 没权限。系统文件夹之类（`System Volume Information`、`$RECYCLE.BIN`） | 正常现象，忽略。真想看就用管理员身份运行 |
| 文件或目录损坏 | **你的盘/文件系统坏了**，这一块目录结构读不出来 | 见下面 |
| 数据校验错 | 磁盘有坏道 | 见下面 |
| 文件被占用 | 别的程序正开着它 | 关掉那个程序再扫 |
| 文件已不存在 | 扫描过程中被删了 | 忽略 |

**出现「文件或目录损坏」怎么办**

这说明不是本工具的问题 —— 是真的读不出来，你在资源管理器里点进去也会报错。

1. **先把还能读的东西拷到别的盘**（重要：修复过程有可能把坏目录里的数据清掉）
2. 再修：
   - 图形界面：**此电脑 → 右键那个盘 → 属性 → 工具 → 检查 → 修复驱动器**
   - 或者命令行（管理员身份）：`chkdsk G: /f`
3. 修完再扫一次

> 实测一台 U 盘：资源管理器说已用 45.1 GB，本工具只算出 2.05 GB。
> 排查后发现 **64 个文件夹报「文件或目录损坏」**，剩下 43 GB 根本读不出来
> —— 工具没算错，是盘坏了。

> 实测 `D:\Project\codex`：**17.74 GB / 271,841 个文件 / 29,492 个文件夹**。
> 资源管理器同时显示 17.6 GB / 269,878 个文件 —— 差的这点是两次测量之间新产生的文件。

## 速度：用多少摆多少

以前扫一个 27 万个文件的目录要十几秒，因为**不管你看不看，它先把 27 万行全摆进列表**。

现在改成：

- **扫描时只摆顶层那一层**（几十行），其余的先记在内存里
- **点开哪个文件夹，才摆哪个文件夹里的东西**
- **搜索也一样** —— 只摆命中的那些行，不再把整张列表推倒重来

实测（自己造的 2 万条目假目录）：

| | 以前 | 现在 |
|---|---|---|
| 扫描完成 | 好几秒 | **0.2 秒** |
| 列表里摆了多少行 | 20,441 行 | **21 行** |
| 拖动窗口时最长卡顿 | 351 毫秒 | **23 毫秒** |
| 搜一次 | 卡死好几分钟 | **6 毫秒** |

数字一个不少 —— 总大小、文件数、文件类型统计，整个目录都算过。

**代价**：点开一个文件夹时会有几百毫秒的加载。里面东西越多越明显，但基本看不出来。

> 收着的文件夹底下垫的那条细灰行，写的是**里面有几项**（`12 项`）。
> 它存在的唯一理由：Windows 的老规矩是"文件夹底下挂了行才画展开箭头"，不垫就点不开。
> 它平时被收着、根本看不见；点开的那一下真内容立刻摆上来，它就撤了。
> 所以上面写的必须是真数 —— 以前那儿写的是"载入中…"，扫完了还赖着不走，纯属唬人。

> 以前"一按搜索程序就卡死很久"是个真问题：它会把整张列表删掉重新摆一遍。
> 现在改成只摆命中的行。

## 技术说明（不了解也别硬看）

- Python 3，**只用标准库**（tkinter 画界面 + os.scandir 扫盘），没有任何第三方依赖
- 扫描在后台线程做（`AnalysisThread`），用 `os.scandir()` 流式扫描，分批把结果推给界面，所以界面不卡
- 界面是浅色扁平风格：白底卡片 + 单一蓝色强调色，文件夹粗体深色、文件浅灰，一眼分得清
- 自带高 DPI 支持（`SetProcessDpiAwareness`），所以在缩放 125% / 150% 的屏幕上文字也是清晰的，不会糊
- 大小是"累积值"：文件夹自身的大小 = 里面所有东西加起来（目录节点直接缓存，不用每次重算）
